## 一、四界面定义与职责总览

| # | 界面 | 一句话职责 | 用户在此做什么 | 主要消费 | 主要产出 |
|---|---|---|---|---|---|

| 2 | **设计编辑器**（简版） | 审改结构化设计对象 | 审改 Brief 解析结果 / 设计对象（机制、变量、关卡结构）、确认或退回 | Game Design Package | 修订后的设计对象、确认/退回决定 |

## 三、C1–C8 × 界面动作落点

| 阶段 | 机器做什么 | 用户在哪个界面做什么 |
|---|---|---|
| C1 创意与需求解析 | 创意 → 结构化概念 | **编辑器**：确认概念、砍范围 |
| C2 策划与玩法设计 | 概念 → 设计对象（过品类 Schema 校验） | **编辑器**：审改、确认 |
| C3 关卡与内容生成 | 设计对象 → 配置/关卡/素材 | **编辑器**：抽查、采纳/拒绝 |
| C4 程序代码生成 | 设计对象 + **C3 生成的关卡及内容数据** + 运行时模板 → 代码 | **代码查看**：审查代码、标记问题、查看 C7 补丁 Diff 并决定是否采纳 |
| C5 资源整合与组装 | → 可运行项目包 | **画布**：触发组装、看清单 |
| C6 运行测试与预览 | → 试玩 + 冒烟结果 + 错误清单 | **预览**：**亲自试玩**（最高质量信号） |
| C7 问题修复 | 错误 → 定位 → 补丁 | **代码查看/编辑器**：决定采纳 |
| C8 迭代再生成 | 反馈 → 影响定位 → 重生成 | **预览/编辑器**：决定改什么 |

## 四、逐界面信息架构（文字线框）

### 4.1 画布（固定工作流视图）

```
┌────────────────────────────────────────────────┐
│ 项目名 │ 当前阶段高亮：C1→C2→C3→C4→C5→C6→C7/C8 │
├────────────────────────────────────────────────┤
│ [C1 概念 ✓]→[C2 设计 ✓]→[C3 内容 ●进行中]→…    │
│   每节点：状态(○●⏸✗✓) + 产物链接 + 错误数 + 操作  │
├────────────────────────────────────────────────┤
│ 当前待办：C2 设计对象待确认 →[去编辑器]          │
│ 阻塞/错误摘要：C6 冒烟 2 错 →[去代码查看]        │
└────────────────────────────────────────────────┘
```

- **节点状态五值（v0.2 增"待开始"；v0.2 收口澄清待确认与失败语义）**：
  - **○ 待开始**：阶段尚未启动——不需要用户做任何事；
  - **● 进行中**：阶段执行中；
  - **⏸ 待确认**：需要用户作出**明确的业务决策**（确认设计对象、采纳补丁等）；
  - **✗ 失败**：阶段**执行异常**——用户可**查看原因、重试或退回处理**（错误处理信号）；
  - **✓ 完成**。
  - ⏸ 与 ✗ **都是用户介入点，但语义不同**：前者是业务决策，后者是异常处理——不得混为一种状态；
- **只读与操作分离（v0.2 补）**：固定工作流图的**节点与连线不可编辑**（只读展示 C1→C8 固定管线）；节点上允许**受控阶段操作按钮**（如 C5 触发组装、失败节点重试、待确认节点跳转对应界面）——操作集合由状态机定义，**不提供自由编排**；
- 每节点产物链接直达对应界面的对应对象（编辑器开设计对象、代码查看开文件、预览开运行入口）；
- MVP **不做**：节点拖拽、自定义连线、自由编排。

### 4.2 设计编辑器（简版）

```
┌────────────────────────────────────────────────┐
│ 对象导航：Brief / 设计对象(机制|变量|关卡|界面描述) │
├────────────────────────────────────────────────┤
│ 表单/结构化审改区（按品类 Schema 字段渲染，       │
│   校验错误就地标注——Schema 校验闸门 UI 化）       │
├────────────────────────────────────────────────┤
│ [确认 → 触发下一阶段]  [退回 → 带修正意见]        │
└────────────────────────────────────────────────┘
```

- 结构化审改，不做自由文本改写（设计对象过 Schema 校验，与前置 2 衔接）；
- C8 影响定位结果在此回显（受影响对象高亮）。

### 4.3 代码查看

```
┌────────────────────────────────────────────────┐
│ 文件树（Build Package 清单）│ 只读代码区          │
├────────────────────────────────────────────────┤
│ 检查报告页签：静态检查 / 冒烟结果 / 错误清单       │
│ C7 补丁页签：Diff 查看 │ [采纳] [拒绝] [退回]     │
│ [标记问题 → 喂 C7]（只打标，不在此改代码）         │
└────────────────────────────────────────────────┘
```

- **代码本体严格只读**——MVP 不做在线代码编辑，修改走 C7 修复流程（AI 生成补丁、用户决定采纳）；
- **C7 补丁操作（v0.2 补）**：C7 生成的修复补丁以 **Diff 视图**展示（改动前后对照），用户可**采纳 / 拒绝 / 退回**——采纳后补丁生效并重走受影响阶段；这是代码查看界面唯一的写操作，且对象是补丁决策、不是代码文本；
- 错误按 Test & Iteration Report 分类展示（设计/代码/资源）。

### 4.4 预览（iframe）

```
┌────────────────────────────────────────────────┐
│ iframe 游戏运行区（生成的游戏在此试玩）            │
├────────────────────────────────────────────────┤
│ 冒烟结果摘要 │ 试玩反馈录入：问题+感受 →[提交]     │
└────────────────────────────────────────────────┘
```

- 现成素材：Spike 各游戏 index.html 的运行页形态（HUD/状态行/事件日志/重开按钮）即预览区的**降级基线**；
- 试玩反馈结构化录入（自由文本 + 问题对象关联），提交后进入 C7/C8。

## 五、全局导航

- 顶部常驻：**当前项目名称 + 画布入口**（v0.2 移除 MVP 项目切换功能——单项目单画布，切换能力不做）；四界面均从画布节点跳入，完成后回画布；
- 界面间跳转只经画布节点链接与界面内动作按钮，不做自由多级路由。

## 七、明确不做（投入控制）

- 高保真视觉稿、交互原型、组件库；
- 画布自由编排/拖拽（§8.4 分阶段开放）；
- 代码在线编辑（修改一律走 C7 流程）；
- 移动端适配；
- 多项目并行工作台管理（单项目单画布即可）。

## 修订记录

- **v0.2（2026-11-12，曦审阅意见六条一致性修订）**：
  1. **画布只读与操作分离**：固定工作流图节点与连线不可编辑（只读）；节点允许**受控阶段操作按钮**（触发组装/重试/跳转），操作集合由状态机定义，不提供自由编排；
  2. **代码查看加 C7 补丁操作**：新增 C7 补丁页签——Diff 查看 + 采纳/拒绝/退回；代码本体维持严格只读，补丁决策是唯一写操作，不增加在线代码编辑；
  3. **C4 输入修正**：设计对象 + **C3 生成的关卡及内容数据** + 运行时模板——C3→C4 数据依赖明确；
  4. **全局导航移除 MVP 项目切换**：只展示当前项目名称与画布入口；
  5. **画布节点状态加"待开始"**：状态五值 ○待开始/●进行中/⏸待确认/✗失败/✓完成——区分阶段尚未启动与需要用户确认；
  6. **iframe 沙箱前置条件**：登记保留为开放问题，注明**首次执行生成代码前必须确定安全边界**，沙箱未定不得运行生成产物。
  - 不增加视觉稿、交互原型和新界面；不启动 G1，不修改运行时代码。
- **v0.1（2026-11-12）**：初版。事实底座 = S4 v2.1.2 §4 第 7 项四界面定义 + 产品架构 v3.1 §二/§三（C1–C8 用户动作、四数据契约、固定管线约束）+ 现有素材盘点。交付 = 四界面职责、契约映射、动作落点、文字线框、降级声明、明确不做清单。

**验收结论（2026-11-12，曦）**：✅ **前置 4 通过验收**——八项审查全部通过（四界面职责 / 四类数据契约映射 / C1–C8 阶段落点 / 画布只读与受控操作 / C7 补丁 Diff 机制 / C3→C4 数据依赖 / 单项目 MVP 导航 / iframe 安全前置要求）。曦特别认可 iframe 原则：**安全边界没有确定之前，不允许运行任何生成的游戏代码**——必要的运行前置条件，不因赶进度跳过。同日收口补记两处交互口径统一（C4 用户操作对齐只读原则 / ⏸ 待确认与 ✗ 失败语义分离），未增加新功能、未升版。**文档冻结 v0.2，停止文档迭代。**
