# 07 评测 · 目录说明

**用途**：放评测方案——怎么判断"这类工具到底有没有用"，包括对照设计、判定口径、样本要求。

**现状**：v0.1 阶段没建正式评测，原因写在 `02_业务访谈/假设可检验化.md`：
- 访谈样本只有 3 位游戏从业者 + 2 位工业对照，任何"效率提升 X%"的对比都做不出置信度；
- 真实场景里也没法做 A/B（没人愿意把线上活动交给一个原型跑）。

**定位**：v2.0 的评测纪律（GT、评测集隔离、基线对照）**未启动，属已知欠账**——v0.2 的最小版是拿雾隐镇任务图当 GT：人为注入 N 处不同步，看结构检查 + 三态判定能检出几处。

**已做的替代**：用三态判定（V-01/V-02/V-03、H-01~H-04）代替评分，用公开事故公告代替"事故发生率"。
将来真要做评测，这里应该放：① 同一份配置，人工核对 vs 工具列清单的耗时对照；② 遗漏率（人为注入 N 处不同步，看工具能检出几处）。
