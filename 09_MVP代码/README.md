# gdw · 工作台第一个能力切入（v0.1 实现）

> 隶属「AI Game Design Agent Workbench」愿景的**质量检查与诊断**环节；
> 本包当前覆盖：配置规则检查、任务可达性三态判定、变更影响分析。

> 这是 `08_原型与界面/设计影响分析器_放置活动配比.html` 背后的**可运行实现**。
> HTML 那份是演示，只认内置三档；这一份能装别人的配置表，换品类不用改代码。

**它回答一个问题**：改一个配置字段，还有哪些已登记的引用要跟着改。

## 一分钟跑起来

```bash
cd 09_MVP代码

# 1. 看配置能不能读
python -m gdw validate fixtures/activity_v0.1.yaml

# 2. 只跑规则
python -m gdw check fixtures/activity_v0.1.yaml --rules fixtures/rules_v0.1.yaml

# 3. 算一次改动的影响面（默认输出纯文本，直接能粘微信）
python -m gdw impact fixtures/activity_v0.1.yaml --rules fixtures/rules_v0.1.yaml \
    --set tiers.T_MID.count=8

# 4. 手上有新旧两版配置？不用手写 --set，直接比
python -m gdw diff fixtures/activity_v0.1.yaml fixtures/activity_v0.1_改后.yaml \
    --rules fixtures/rules_v0.1.yaml
```

只依赖 Python 3.10+。YAML 需要 `pyyaml`，读 Excel 需要 `openpyxl`——两个都不装也能跑 JSON。

输出长这样（`out/变更确认单_示例.md` 是完整版）：

```
【活动变更确认单】霜月祭｜2026-11-10 16:19
一、本次改动 1 项
  · 中档 · 数量：5 → 8
二、规则 6/8 通过，2 条违反
  × R-03 中档人数与声明一致（阻断）：中档配置值与声明值不一致
  × R-05 中档占比落在区间内（高）：中档占比超出 0.3%–0.6%
  （分层看：口述 4/4，工程假设 2/3，模拟阈值 0/1，不能合成一个总数）
三、需要确认的对象 4 个
  □ 活动公告文案（运营）｜直接引用｜tiers.T_MID.count
  ...
```

命令行退出码：有**阻断级**违反返回 1，否则 0。可以直接挂到提交前检查里。

## 三条设计选择

**1. 档位不是写死的。**
`tiers` 是「按 id 索引的数组」，路径写 `tiers.<档位ID>.<字段>`。所以：

- 三档活动换成五档累充，代码不动（见 `fixtures/activity_accumulate_5tiers.yaml`）；
- 字段从 `ratio/count` 换成 `amount/reward_points`，代码不动；
- 增删档位、调整顺序，**引用路径不会失效**（按 id 找，不按下标）。

这套验证就是 `tests/test_model.py::SecondShapeTest`——第二套配置和第一套没有任何共同字段，照样跑通；
跨表那套（`tests/test_cross_table.py`）再验一次：表名、行 id、字段三段都能解析，改哪一行只命中引用那行的对象。

**2. 规则属于数据集，不属于产品。**
规则写在独立规则包里，每条 = 一句条件表达式 + 来源分层 + 级别：

```yaml
- id: R-01
  name: 产出比 1:10:100
  level: 阻断
  source: oral          # oral / eng / sim —— 来源必须留在数据里
  when: tiers.T_LOW.ratio * 10 == tiers.T_MID.ratio and tiers.T_MID.ratio * 10 == tiers.T_HIGH.ratio
```

表达式由 `gdw/expr.py` 求值，**不用 eval**：只放行白名单的 AST 节点和 `round/min/max/len` 这类函数，
出现 `__import__`、`open`、赋值语句一律报错。规则文件可以交给非程序员改，不会把进程交出去。

`source` 三层（口述 / 工程假设 / 模拟阈值）不是装饰：报告里必须按层展示，
**不许把「8/8 通过」合成一句话对外说**——工程假设那几条本来就没有受访者依据。

**3. 支持跨表。**
真实配置表里，活动表只存道具 ID，名字 / 堆叠 / 售价在另一张道具表上。所以配置可以带 `tables`：

```yaml
tables:
  items:
    - { id: "10086", name: 霜月结晶, max_stack: 999, sell_price: 10 }
```

引用就写 `items.10086.name`——**第一段表名、第二段行 id、第三段字段**，refs 和规则表达式共用一套写法
（Python 语法里 `items.10086` 不合法，求值前会改写成 `items["10086"]`，写规则的人不用记两套）。

**表之间还能互相指（多跳）**。配一条 `links` 就够了，不用写代码：

```yaml
links:
  - from: drops.item_id    # 这一列存的是 items 的行 id
    to: items

tables:
  drops:
    - { id: "5001", name: 常规掉落组, item_id: "10086", weight: 30 }
```

之后引用写 `drops.5001.item.name`——「5001 这个掉落组绑定的道具叫什么」。
求值时它会走两跳，并把**经过的那一跳也记进依赖**：

| 引用 | 落到 | 中间经过 |
|---|---|---|
| `drops.5001.item.name` | `items.10086.name` | `drops.5001.item_id` |

所以改 `items.10086.name`（换名字）和改 `drops.5001.item_id`（换绑道具）**都会**把「掉落预览面板」算进影响面。
单看字符串路径是推不出来的，这是多跳唯一的价值点，也是 `tests/test_cross_table.py` 里钉死的那两条。

规则里也能直接读跨表字段：`drops.5001.item.sell_price <= 20`（`_id` 之后的别名由系统补，写规则的人不用记两套）。

Excel 里更简单：**除固定四张表外，任何 sheet 都当成外部表，sheet 名就是表名**；
再加一张 `links` 表（两列：from / to）说明谁指向谁。

改道具表里一个字，只会命中引用它的那个浮窗，不会连累邮件——`tests/test_cross_table.py` 里钉着这条。

**换绑 ID 时会明说推不出来**：把 `tiers.T_MID.item_id` 从 `10086` 改成 `10087`，系统只会提示「引用 `item_id` 的对象」；
那些引用 `items.10086.*` 的对象从字符串路径上推不出来。它不硬猜，但会单列一节：

> 四、推不出来的部分（必须人工确认）
> ! 中档 · 绑定道具 从 10086 换成了 10087：引用旧行 items.10086.* 的「道具浮窗」不会自动出现在上面……

宁可多一行"我不知道"，也不能让单子漏得莫名其妙。

**4. 影响面只沿「已登记」的引用推导。**
三种关系分开标，不混成一个数：

| 关系 | 含义 | 例 |
|---|---|---|
| 直接引用 | 对象直接引用了被改字段 | 公告文案引用 `tiers.T_MID.count` |
| 派生失效 | 该字段由被改字段算出来，得重算；引用这个派生值的对象也算受影响 | 改服务器人数 → 低档份数失效 → 邮件、掉落跟着变 |
| 上级字段 | 改的是父级路径，引用其子字段的对象也算 | `--set tiers.T_MID=...` |
| 跨表 | 引用经 `links` 跳到另一张表，命中的是那一行或中间那个 `_id` | `drops.5001.item.name` |

没登记的引用**查不出来也不会假装查得到**。这是这个工具敢被相信的原因，也是它的天花板。

## 脏表压测（接真表的准入条件）

`tools/make_dirty_fixture.py` 生成一份**故意难看**的表（`fixtures/脏表_真实形态.xlsx`），
难点全是真实世界里见过的：合并单元格大标题、表头不在第一行、中文表头、数字存成文本还带空格、
空列、空行、引用分隔符混用（顿号/分号/逗号）、没有 id 列的 junk sheet、id 一边数字一边文本。

`tests/test_dirty_xlsx.py` 钉死了 loader 必须扛住的清单：

- 前 10 行内自动找表头（合并标题不算表头）；
- 常见中文表头归一成标准字段名（产出比→ratio、售价→sell_price……认不出的表头**原样保留**，refs 照着写就行）；
- 数字存成文本、带全角/半角空格，都转回数字；
- 引用分隔符顿号/分号/逗号/换行混用都拆得开；
- 没有 id 列的 sheet 跳过，但记进 `_meta.skipped_sheets`——**不静默吞**；
- id 是数字还是文本都能按 id 找到行。

结果：这份脏表直接跑出 8/8 规则通过 + 正常的变更确认单。**接真表前不再需要"先把表整理干净"。**

**仍然不扛的（遇到就得人工处理）：**

- Excel 里的**公式**：读的是缓存计算值，没保存过结果的公式读到空；
- **合并的数据单元格**（表头合并可以容忍，数据区合并不行——一个格子里到底是谁的值说不清）;
- 一个 sheet 里塞两种表；
- 表头别名表是枚举的，遇到新叫法要往 `_HEADER_ALIASES` 里加一行（一行代码的事，但得加）。

## 真表压测（PokeAPI 数据，1260 行）

`tools/make_real_fixture.py` 把 **PokeAPI 的真实 CSV**（937 条招式 / 21 种属性 / 300 只宝可梦，
全部真实数值）拼成一本配置簿：`fixtures/真表_宝可梦数据.xlsx`，配 `rules_real.yaml`。

它比脏表更狠的三个地方：

- **行 id 带横杠**：double-edge 是 38 号，`moves.38.identifier` 这种路径表达式也要能走
  （`normalize` 已泛化：段不是合法标识符就改下标，数字和横杠都覆盖）；
- **大量空单元格**：状态招式没有 power/accuracy——规则引用到空字段时判定为「无法判定」，不是崩溃；
- **真实外键**：`moves.type_id → types` 是真链接，改 `types.1.identifier` 会把两条多跳引用的对象都算进影响面。

性能：1260 行数据 validate 约 1.1 秒，check 约 1.2 秒。

★过程中发生了一件值得记录的事：我凭印象写规则「moves.25 是第二世代的 double-edge」，
真数据当场打脸——25 是 mega-kick（第一世代），double-edge 是 38 号、也是第一世代。
错误版本留在 `rules_real.yaml` 的注释里，`tests/test_real_fixture.py::test_real_data_corrects_assumptions`
把这次打脸钉成了一条断言。**规则靠印象写就是会错，这正是「规则必须带来源、必须可回查」的原因。**

CSV 没下载时 `tests/test_real_fixture.py` 整套自动跳过，不依赖网络。

## 给别人用的回路

1. `python -m gdw template 我的配置.xlsx` 生成模板（四张表：activity / tiers / downstream / derived）
2. 对方按自己的表填，`refs` 一列写 `tiers.T_MID.count` 这种路径，分号隔开
3. `python -m gdw impact 我的配置.xlsx --set ...` 直接出确认单

除这四张外，想加外部表就直接加 sheet（比如 `items`、`drops`、`shop`），表名即 sheet 名。

Excel 只认固定四张表的名字和列名。这**不等于**支持任意真实配置表——
真实表通常有几十列、多级引用、道具 ID 引用道具表，那是另一件事，本版没做。

## 边界（v0.1 冻结于 2026-11-10）

1. **只做已登记引用。** 公告里手写的数字、公告图、截图里的旧值，本版查不出来。
   公开事故公告里最常见的一类错（见 `02_业务访谈/二手证据卡.md` 附录 D）正落在这一块外面。
2. **「已同步」是人工勾的。** 系统只知道「受影响」，不知道有没有人去改。真实接入应该挂版本号 / 任务单 / 提交记录，本版没接。
3. **派生只支持单层。** 公式引用的还是配置里的原始字段，不做链式重算。
4. **版本对比只比数值。** `diff` 摊平 activity / tiers / tables 的标量字段，但不展开跨表链接（改道具名不会显示成"掉落组变化"）；downstream / derived 属于结构定义，改了它们不进入 diff（会作为「结构变化」提示，不推导影响）。新增 / 删除档位同样只提示、不推导。
5. **规则靠人写。** 它不产生规则，只执行规则。规则写错，结论就错——所以每条规则都带来源，方便事后追责到人。
6. **跨表最多三跳。** `links` 可以链起来（drops→items），但别名展开有深度上限 3，防互相指来指去死循环。更深的结构建议先拆表。
7. **链接字段必须以 `_id` 结尾。** 别名（`item_id` → `item`）是机械推出来的；不结尾就没法判断它是引用还是普通字段，校验会直接拦下。
8. **别名和真实字段重名时，真实字段优先。** 比如某行自己就有 `item` 字段，那就不会展开链接——这种情况建议改链接字段名，别硬撞。
9. **规则现在有两处实现。** `08_原型与界面/设计影响分析器_*.html` 里是 JS 版（冻结不再改），本包是 Python 版。
   两边结论一致时无所谓，不一致时**以本包为准**——它带测试，HTML 那份没有。将来前端应该改成调本包输出的 JSON，而不是自己再算一遍。
