## 一、v1.1 两处修正（曦阻塞问题的解决）

### 修正 1：数据通道改为「fetch JSON + 受控 postMessage」（不再脚本化加载）

**v1.0 缺陷**：数据以 `window.__GAME_DATA = {...}` 形式作为同源 `.js` 文件经 script src 加载——浏览器将其作为 JavaScript 解析，违背"生成产物只允许 JSON 数据"原则。

**v1.1 决定**：
1. 生成数据 = **纯 JSON 文件**，服务端以 **`application/json`** 提供（MIME 由服务器保证，附加 `X-Content-Type-Options: nosniff`）；
2. **宿主页 fetch** 该 JSON，经 `json-fetch.js` **受限流式读取**（Content-Length 头筛 → 流式字节计数超限即 cancel → JSON.parse），数据永不进入 JS 求值路径；
3. 经**受控 postMessage**（type=`pipeline:data`，方向 `hostToGame`）递入游戏帧；
4. 游戏帧固定引导脚本双重校验（消息守卫 + 数据契约守卫）后才接受；
5. 游戏帧 **CSP `connect-src 'none'`**——帧内无任何网络能力；宿主 CSP `connect-src 'self'`——只许 fetch 本地数据文件。

**为什么不会把生成数据转化为可执行代码**：JSON 文本只经 `JSON.parse`（数据语义，不产生函数与作用域）；postMessage 走结构化克隆（同样只产生数据）；生成文本进入 DOM 只经 `textContent` / `escapeHtml`（惰性展示）。三个通道没有任何一个把字符串当作代码求值。

### 修正 2：运行放行条件（三级闸门，取代"M0 验收即开放运行"）

```
M0 通过（本记录） = 安全隔离基础设施就绪
+ M2 通过          = 完整 Schema 校验 + GT-1 可解性验证
→ 此后才允许 M3 运行生成产物
```

**M0 验收通过仅代表安全隔离基础设施通过，不开放任何生成产物运行。** 运行放行权在 M2 闸门完成之后。

## 二、安全边界决定（四层防线 + 消息校验）

| 层 | 决定 | 实现位置 |
|---|---|---|
| 1. 数据契约隔离 | 生成产物只允许 JSON；严格解析（非 JSON / 污染键 / 越限一律拒） | `security/strict-json.js` |
| 2. 原型污染防护 | `__proto__`/`constructor`/`prototype` 键入口拒绝（纵深防御） | 同上 |
| 3. 安全级契约守卫 | 信封键/版本/类型/规模检查；**不审文本内容**（合法可疑文本放行、展示层惰性化）；完整 Schema 属 M2 | `security/data-guard.js` |
| 4. 装配与运行隔离 | 游戏页 CSP `script-src 'self'` + `connect-src 'none'`；宿主 `sandbox="allow-scripts"`（无 allow-same-origin）→ opaque origin；文本一律 `textContent`/`escapeHtml` | `security/assemble.js` |
| 5. 消息通信校验 | 双方向白名单（hostToGame: `pipeline:data`；gameToHost: win/log/state/error）+ 字段类型/长度 + 来源校验（ev.source，**来源不匹配同样计入丢弃计数**）；不合规静默丢弃 | `security/postmessage-guard.js` |
| 6. 固定引导脚本 | 游戏帧/宿主引导均为一方代码（非生成物），可审计 | `security/game-bootstrap.js`、`security/host-bootstrap.js` |
| 7. 受限 JSON 拉取 | 宿主拉取生成数据的三道顺序：**Content-Length 头筛（超限不读 body）→ 流式读取逐块计数（超限立即 cancel）→ JSON.parse**——大小限制先于解析（曦审阅口径 2） | `security/json-fetch.js` |

## 四、测试结果 · 第二层：真实浏览器实测（系统 Edge/Chromium，playwright-core 驱动，13/13 通过）

实测环境：`security/test-server.js`（127.0.0.1:8791）+ `security/browser-tests.js`（headless Edge）。测试样本标题故意含 `<script>alert(1)</script>`（合法文本惰性展示的实测载体）。

| # | 实测项 | 结果（浏览器实际行为） | 对应核验重点 |
|---|---|---|---|
| BT0 | 宿主页+游戏帧加载 | **控制台 0 错误** | — |
| BT1 | iframe sandbox 属性 | `sandbox="allow-scripts"`，**无 allow-same-origin** | iframe 隔离 |
| BT2 | 数据 MIME | `Content-Type: application/json; charset=utf-8`（**非脚本类型**） | 数据通道 |
| BT3 | 数据通道走通 | 游戏帧经受控 postMessage 收到数据，状态 = `DATA OK: <script>alert(1)</script> 测试游戏 🎮` | 数据通道 |
| BT4 | 惰性展示 | 敌意标题**只显示为文本**（textContent），帧内**无**含 alert(1) 的脚本节点 | 文本注入 |
| BT5 | 游戏帧 CSP 就位 | meta CSP 实际生效：`script-src 'self'` + `connect-src 'none'` | CSP |
| BT6 | **外网访问拦截** | 游戏帧内 fetch 外部地址 → `BLOCKED: Failed to fetch`（CSP 拦截） | 外网访问限制 |
| BT7 | **opaque origin** | 游戏帧访问 localStorage → `BLOCKED: SecurityError` | iframe 隔离 |
| BT8 | **宿主访问限制** | 游戏帧读 `parent.location.href` → `BLOCKED: SecurityError`（跨源） | 宿主访问限制 |
| BT9 | **postMessage 类型校验** | 游戏帧发 `evil:exec` → 宿主**丢弃**（__DROPPED 计数）；发合法 `game:win` → 正常放行 | postMessage 校验 |
| BT10 | 脚本面干净 | 帧内 4 个脚本全部为 `/engine/` 固定一方 src，**无内联、无生成数据脚本** | 数据通道 |
| BT11 | **超大响应解析前拒绝** | `/data/big.json`（300KB 不闭合 JSON，无 Content-Length 走流式）→ `PAYLOAD_TOO_LARGE (stream @ 307206 bytes 解析前中止，未完整读取)`；若限制在解析后应报 INVALID_JSON——实测否定了该可能 | 大小限制先于解析 |
| BT12 | **来源校验实证** | 无关的第二个游戏实例帧（`/play/g2`，真实加载的无关窗口）发送**合法格式** `game:win` → 宿主经 event.source 校验丢弃（SOURCE_MISMATCH），game:win 事件数不变（1→1），丢弃计数增加 | postMessage 来源校验 |

复跑方式：`node security/test-server.js`（保持运行）+ `node security/browser-tests.js`

**五项重点核验对应关系**：CSP → BT5/BT6；iframe 隔离 → BT1/BT7；宿主访问限制 → BT8；外网访问限制 → BT6；postMessage 来源校验 → **BT9（类型维度）+ BT12（来源维度）**。全部为**真实浏览器行为**（系统 Edge/Chromium，headless），非 Node 单元模拟。

**BT12 补充说明（测试载体选择）**：最初用 about:blank iframe 作无关窗口，实测发现其 postMessage 派发不可达（消息未到达宿主，顶层监听器亦未收到——浏览器对 about:blank 初始文档的消息派发行为所致），遂改用**真实加载的无关游戏实例帧** `/play/g2` 作为无关窗口载体——语义更强（是一个真实运行的无关实例）且可实测。诊断同时确认：宿主对来源不匹配消息的丢弃计数已覆盖（v1.1 修正：来源不匹配也计入 __DROPPED，不再 early-return 跳过计数）。

## 五、边界与后续

- 本记录覆盖数据安全与运行隔离；M2 叠加完整 Schema 校验与 GT-1（串联闸门）；
- **运行放行 = M0 + M2 双闸门齐备后**，M3 才组装运行生成产物；
- M1 期间只生成 JSON、不提前执行（曦约束）；
- M3 接入真实引擎时，引擎文本渲染路径（textContent vs innerHTML）按"惰性展示"原则复核。
