## 一、安全边界决定（四层防线）

| 层 | 决定 | 实现位置 |
|---|---|---|
| 1. 数据契约隔离 | **生成产物只允许是数据（JSON）**——G1 管线只生成 JSON，不生成可执行代码。产物经严格解析注入固定引擎，全程无 eval / 无 Function / 无脚本标签注入 | `12_G1_生成管线/security/strict-json.js` |
| 2. 校验前置 | 数据契约守卫（安全级）：信封键/版本/类型/规模四类结构检查——结构非法不组装不运行；**完整 Schema 校验属 M2**，本层只挡安全级非法 | `security/data-guard.js` |
| 3. 原型污染防护 | `__proto__` / `constructor` / `prototype` 键在解析入口直接拒绝（纵深防御：JSON.parse 自身不触发污染，但下游 Object.assign/展开可能被利用） | `strict-json.js` walk |
| 4. 装配与运行隔离 | ①数据以**同源外部数据文件 + script src** 注入，内容转义 `<` `>` U+2028/2029（防 `</script>` 逃逸）；②游戏页 **CSP**：`default-src 'none'; script-src 'self'; connect-src 'none'`（禁外联、禁内联、禁 eval）；③宿主 **iframe `sandbox="allow-scripts"`**（无 allow-same-origin）→ 游戏帧 opaque origin，无法触宿主 DOM/存储/Cookie；④生成文本一律 **escapeHtml 惰性展示**，绝不 innerHTML 原样注入 | `security/assemble.js` |
| 5. 消息通信校验 | 游戏帧 opaque origin → origin 恒为 null，无法用 origin 白名单；替代三层防线：**event.source 必须是游戏帧 contentWindow** + 消息形状白名单（4 类型）+ 字段类型/长度校验；不合规静默丢弃并记原因 | `security/postmessage-guard.js` |

**宿主页面隔离说明**：游戏帧与宿主之间唯一通道 = postMessage（经上述校验）；游戏帧无同源权限，宿主不向游戏帧暴露任何对象引用。

## 二、两类安全测试判据（曦审阅口径的落实）

- **A 非法数据拦截**：结构非法 / 污染尝试 / 越限——**一律拒绝**（10 项）；
- **B 合法文本惰性展示**：合法字段里的可疑字符串（如含 `<script>` 的标题）**不拒绝**（它们是合法文本），但展示层转义惰性化，不成为可执行标记（5 项）；
- **C 通信与隔离**：消息白名单、来源校验、sandbox 属性、CSP 收紧（9 项）。

## 四、边界与后续

- 本记录覆盖**数据安全与运行隔离**；M2 将叠加完整 Schema 校验（结构/白名单/LIMITS/交叉引用）与 GT-1 可解性——两层是串联闸门，不是互替；
- 运行时引擎（grid_engine/dsl_runtime）在 M3 接入组装时，其文本渲染路径（textContent vs innerHTML）将按本记录"惰性展示"原则复核；
- M0 验收通过后，**开放生成产物运行**；M1 期间仍只生成 JSON、不提前执行（曦约束）。
