## 三、签收所依据的红线（摘要，原文见决策包）

1. **生成 ≠ 匹配**：预置仅限引擎能力原语（网格/移动/回合/碰撞/状态变量/事件/渲染），玩法规则必须由 AI 从 Brief 生成；新机制合法性 = Schema 校验 + Runtime 执行 + 可解性 + 试玩四步全过，无任何"类似已注册玩法"要求；
2. **三层口径强制区分**：产品愿景 / 第一阶段 MVP / 当前已实现（以代码和测试为准）——任何文档与汇报不得越层表述；
3. **BFS/求解器结论 ≠ 游戏质量**：GT 三值语义（PASS 候选 / UNSAT 双前提 / UNKNOWN 禁止放行），真实通关证据 = Runtime 重放，意图与体验由人类裁决；
4. **安全边界前置**：iframe 沙箱等级确定之前，不运行任何生成产物；
5. **不因已实现能力改变产品定位**：变更影响分析等现有能力是管线中的质量关卡与迭代定位器，不主导路线排期。
